## ★ Write first: Crawl Is an MCP, Not a Chatbot

**Thesis:** If you already use Power BI and have already used a chatbot, “ask ChatGPT for a rolling 12-month” is crawling in a circle. Point the agent at the semantic model MCP and ask what it can do. That is motion.

**Material (Tommy):**
- Agrees you cannot skip AI in this job. Distinction: the tooling in the workflow, not “AI” as a buzzword. Will not start someone on an MCP as a blank-slate first second. The audience is not a blank slate.
- Megan’s crawl examples (rolling 12-month DAX, small multiples, theme JSON) are fine as trivia. Without *this* model they mislead more than they help. You get a generic RANKX and still cannot do it. Chicken piccata recipe, someone else’s kitchen.
- His 2024 move: screenshot the model, ask in one chat. That was crawl. He has outgrown it as the prescribed first step. Separate-harness chat is tedious instruction-dumping.
- If IT installs the Power BI modeling MCP, crawl is: you have this server, I do not know what to do, what can you help with. User does not have to install anything.
- Chatbot crawl = circling. MCP-against-the-model crawl = actually going somewhere.

**Attribution:** Tommy, disagreeing with Megan (and with Mike, who still wants chat as step one because “most people already crawled without knowing”). Mike agrees MCP is a good start once granted.
**Freshness:** fresh. Adjacent to Don’t Let Agent Touch Fabric (MCP *survey before write*). This is MCP as the *learning* crawl, not the session safety gate.

## Other angles

### Don’t Collect TMDL as a Cover Charge
**Thesis:** Walking a Power BI person through VS Code, PBIP, and TMDL before they get an agent is extra tooling they do not need yet. Claude Desktop plus the modeling MCP is the walk. The IDE is the run.
- Megan: walk = code editor, run = skills + MCP. Tommy swaps them.
- Odds that a chatbot-only PBI person has been living in an IDE: low. Drop VS Code + PBIP + “welcome to TMDL” and you break the motion.
- MCP works in a chatbot. Skills are easy to start in Claude Desktop. VS Code is a full file/SDLC view.
- Walking-to-run for him is reading diffs and approving, not hand-editing.
**Attribution:** Tommy. Do not write Mike’s 70–80% harness stat as Tommy’s.

### Skills Are the Walk, Not the Finish Line
**Thesis:** Repeating yourself across chats is the signal you are ready for skills. Calling skills the “run” stage leaves people walking into a wall with a generic model.
- Whatever you call the middle stage, you need to be comfortable with skills there. Without them you walk into a wall.
- Megan puts skills + MCP at run / “really finding success.” Tommy: that is too late for walk.
- Shared definition: skills = reusable process you give every session after you notice you keep saying the same things. MCP = hands (create table is a tool with inputs, not the agent inventing TMDL).
- Why they talk Claude: Anthropic shipped skills, machine/MCP integration, file-native Code/Cowork, then open-sourced skills. That was the tipping point.
**Freshness:** Skill Vault is the packaging product, not this progression argument. File as Idea.
